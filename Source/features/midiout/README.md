# Detector MIDI output

The original `MidiOutEmitter` and its three parameters retain their modes, ranges, note mapping and default finish behavior. The additive `MidiScheduler` is selected only by `fl11_on`; all twelve `midiext` IDs are routing/performance state and use AU parameter version hint 3. Release MIDI output declarations remain controlled by `GAPFILL_MIDI_OUT`, off by default.

`EngineEventBuffer` is an optional fixed 64-event producer log. Hit, GapOpen and Confidence values are normalized 0–1; FillStart also carries planned length in samples. Normal positions use the engine output timeline. A separate input-domain Hit log feeds `consumeEarlyHits`; only Hit notes move early. Confidence is sampled by the producer only when enabled. GapClose survives overflow by replacing a non-closing event.

The audio-thread owner calls `prepare`, then for each callback `beginBlock(settings, outputStart, samples, inputStart, eventBudget)`, feeds every chunk log, and calls `finish` or pure packet `render` exactly once. Events from early and output sources are merged by wire time before updating note ownership. Three active types use unique physical note/channel ownership, same-sample retriggers coalesce, note-offs precede retriggers, and deadlines survive host-block boundaries. Gap and Fill durations have a 1 ms floor. FillStart schedules its own planned end; an unrelated older voice's FillEnd cannot terminate a replacement note.

Storage and loops are bounded. New note-ons/CCs leave three output slots reserved for sounding-note offs. At most 32 packets are rendered. Confidence CC refuses 120+ and is deduplicated by two steps, with at least `ceil(sampleRate/66)` samples between sends. Invalid event types/non-finite strengths are ignored. Explicit flush suppresses new detector notes for that block; the caller must additionally disable event admission during sustained panic or known stopped-host transport. Sample-rate changes retain old note identities until their safe flush.

The processor coordinates legacy/extended handoff: clear incoming MIDI only after MIDI learn and command scanning; flush the previous owner first; pass the remaining 32-event budget to the new scheduler; append new packets with `clearInput=false`. Calling two clearing finish methods would erase the old owner's offs. The legacy one-argument finish API is unchanged; its new append overload is coordinator-only. MIDI buffers must be pre-sized outside audio (2048 bytes exceeds the bounded packet requirement); the adapter does not allocate capacity in callbacks.

Pure packet and actual JUCE-MIDI adapter tests cover all supported rates/block sizes, aligned/early timing, duration, aliases/retriggers, CC limits, overflow, 1000 seeded sequences, flush and ownership handoff under AllocGuard. Root processor/engine wiring, actual wrapper capacity, build option ON/OFF, native format validators and real-host/controller routing are separate integration/acceptance requirements. These standalone module results do not establish hardware or release acceptance.
