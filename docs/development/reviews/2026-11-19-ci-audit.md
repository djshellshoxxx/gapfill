## Confirmed defect and repair

`release-beta.yml` previously accepted a successful ordinary CI run with the
expected platform artifacts even when full assurance was skipped. Its checks
covered the workflow path, commit, conclusion, and artifact names, but did not
require the native full suites, ASan/UBSan, TSan, or performance/soak jobs.

An offline regression executes the actual release verification shell step with
GitHub responses replaced by fixtures. Before the repair, the ordinary-run
fixture incorrectly succeeded and emitted the `run_id` packaging output. After
the repair, it fails before emitting any packaging outputs.

The new `tools/qa/release_source.py` requires all eight full-assurance matrix
rows to have completed successfully in the selected run for the exact commit.
It rejects missing/skipped/cancelled/failed rows, duplicate job identities,
borrowed results from another run or commit, and incomplete pagination. It also
checks any additional assurance rows. The workflow path comparison now requires
the exact CI filename rather than accepting files with that prefix.

The helper uses standard-library JSON decoding for the consecutive pages from
`gh api --paginate`; it does not require the newer `gh --slurp` option. The
existing artifact, signing, package validation and manual acceptance requirements
are retained. The module contract is documented in `tools/qa/README.md`.
