### Integrated stress (`Tests/features/TestIntegratedStress.cpp`)

Seeded, deterministic (`GF_STRESS_SEEDS=N GF_STRESS_SEED0=S` for more). Every block checks: zero allocations on the audio
thread (AllocGuard, which now also sees `malloc`), finite output, no sub-normal output, level <= +6 dBFS (Wet Safety
on, Output <= 0 dB, full-scale input; Band Solo excluded, see findings).

* Everything on: every parameter fuzzed (single tweaks, 40 % storms, "everything on" resets), commands (all 32 types),
  MIDI notes / CC / program change / pitch bend, transport start / stop / loop / seek / tempo / time signature / no
  host info, bypass toggling (`processBlockBypassed`), Randomise / Surprise / Undo / Reset spam, preset load storms,
  state save + load in the middle of playback, panic / recover every block.
* Sample rates 22050, 44100, 48000, 88200, 96000, 192000; block sizes 1, 7, 64, 512, 1000, 8192 fixed and random
  (40 % of random blocks are 1-64 samples); mono / stereo / sidechain / Wet bus layouts; hostile input (silence, DC at
  full scale, Nyquist square, full-scale noise, near-denormal noise).
* NaN / Inf / 3e38 input bursts: the processor is clean again once finite audio returns.
* Concurrent: the audio callback on its own thread while the message thread opens and closes the editor 36 times,
  loads state and presets, fuzzes parameters, posts commands, runs Randomise / Surprise / Undo; editor destroyed while
  audio keeps running.
* Two co-op instances on two audio threads while group / mode are flipped and a third member is created and
  destroyed.

## Bugs found and fixed (root cause)

1. **Audio-thread allocation on the first fill** (`PluginProcessor`, found by the stress test). `Evolve` calls
   `surpriseTargets()`, whose function-local static `std::vector` is built on first use, i.e. inside the first
   `processBlock` that evaluates a decision. Fix: touch it in `prepareToPlay`.
2. **State saved after loading an older state could not be loaded again** (`PluginProcessor::isParameterStateValid` and
   `setStateInformation`, found by the new fixture round trip). Loading a 0.0.1-beta state leaves JUCE's
   `<PARAM id="x"/>` nodes without a `value` for every parameter added since; the next save wrote them, and the
   loader rejected the whole state for a known parameter without `value` -> a project saved by this build, reopened,
   silently came back at default settings. The same missing values also meant a parameter absent from a loaded state
   kept the previous instance's value (residue). Fix: a node without a value is "not stored" (accepted), and such
   parameters are set to their default on restore, which also makes the next save complete. Also applies to
   `.gapfill` preset files (`applyParameterState`).
3. **Groove subtree stale after a restore** (`GrooveState` / `GrooveStateTree`). The restore queues a reset / load for
   the audio thread, so a save made before the next audio block still described the previous groove (not
   reproducible: set-state then get-state). Fix: the serialiser reflects a pending reset or pending load.
4. **Empty combo boxes** (`GapCombo`, found from the first screenshot). JUCE's `ComboBoxAttachment` only maps the
   index; it never fills the list. Mode, Detector Source, Sync Division, Fill Type, Stutter Div, Delay Div (and every
   other `GapCombo`) showed an empty, unselectable box. Fix: fill the list from the choice parameter before attaching.
5. **Auto Weights panel overflow** (`WeightsPanel::resized`). With the 16 bars in one 26 px-per-row column, only 6
   were visible at 1100x700; the rest ran under the preset buttons. Fix: add columns (up to 4, each >= 120 px) until
   the rows fit.
6. **Clipped labels** (`GapKnob`, `CreativePanel`). The default 5 px label border cut "PROTECT HOLD" to "PROTECT
   HO..."; the cell shared by CAPTURE / AUDITION / SHAPE (3 buttons in a 150 px cell) cut "CAPTURE" to "CAPTU...".
   Fix: zero label border, cell minimum 190 px.
7. **IR worker race on re-prepare** (`ConvoCard::prepareCard`, by review). A sample-rate / block-size change
   reallocated `mailbox` and rewrote `sr` while the worker thread could be copying a captured IR from it. Fix: stop and
   join the worker before re-preparing.
8. **Cancelled calibration recording resurrected** (`RecordTap::writeRecording`, by review). The last block stored
   `Done` unconditionally, overwriting a concurrent `cancel()`. Fix: compare-and-swap from `Recording`.

Test-harness changes (no assertion loosened):

* `AllocGuard` was blind to `malloc`/`calloc`/`realloc`, which `juce::HeapBlock`, `juce::Array` and `juce::MidiBuffer`
  use. On Linux/glibc (not in a sanitizer build) it now counts them too; `GF_ALLOC_TRAP=1` prints a backtrace per
  guarded allocation. This exposed two test artefacts, not product bugs: `Formant.no_alloc` and `SpFreeze.no_alloc`
  copied their input buffer inside the guard (now copied before it).
* ASan found an out-of-bounds read in `BusFx.panic_clears_all_cards`: the test drove a block-sized duck buffer with
  growing offsets over a 1 s buffer. The product indexes the duck buffer from the start of a block-sized wet buffer
  (as the processor does), so the test now feeds 512-sample blocks at offset 0.

9. **Quality level read by the UI while the audio thread writes it** (`QualityController`, TSan on the concurrent test).
   `requested` / `applied` / the auto governor's level were plain ints read by the Routing card's timer. Fix: relaxed
   atomics (reads and writes are single words; no ordering is needed).

## Findings not changed

* **TSan inside JUCE:** `juce::dsp::Convolution::loadImpulseResponse` (worker thread) vs `processSamples` (audio
  thread) reports an unsynchronised read of `ConvolutionEngineQueue::pendingCommand`. It is JUCE's own documented-as-
  thread-safe path; not changed. The Convo CPU-budget test also fails under TSan only because of the slowdown.

* **Band Solo overshoot (fixed).** With Band Solo on, the live-retuned Linkwitz-Riley band peaked up to 6.7x on a
  full-scale Nyquist square / DC input while the crossover moved. The solo output now passes `dsp::soloLimit`
  (`Source/dsp/SoloLimit.h`): identity for |x| <= 1, smooth tanh bend to a ceiling of 2 (+6 dBFS) above; normal levels and
  the golden files are unchanged, and the stress test no longer excludes Band Solo from the +6 dBFS bound
  (`TestSoloLimit.cpp`).
* **Level contract depends on the user's gains.** The wet limiter bounds only the wet bus: dry + wet can exceed
  +6 dBFS with Output above 0 dB, Wet Safety off, or the A/B match trim (up to +6 dB). By design.
* **clap-validator warning:** `state-invalid-random` loads 3 MB of random bytes "successfully" (no crash). The
  loader is deliberately fail-soft; `setStateInformation` cannot signal failure to the host.
* **Scrub row layout (fixed).** The detached SCRUB row is now a foldable "Scrub" card at the top of the Effects drawer
  (`ScrubCard.cpp`): the SCRUB switch in a 28 px header, Position / Width as two compact bars that appear only while it is
  on. Nothing is registered for `Slot::PerformanceStrip` any more, so no row is carved from the visualiser. Parameter IDs
  are unchanged.
* The visualiser is empty in the screenshots: the test editor is never fed by a running audio thread.

## Thread safety (static review)

* No lock is taken on the audio thread anywhere (`CriticalSection` exists only in `ConvoCard`, worker / message
  thread). Cross-thread state is atomics, `TripleBuffer`, SPSC queues (`CommandQueue`, `FillEventQueue`, `UiRequest`,
  MIDI-learn arrays) with documented producers; overflow drops and counts (`getDroppedFillEvents`, `getDroppedUiRequests`).
* Worker threads: `ConvoCard` (joined in the destructor and now before re-prepare), `CalibrationSession::Job` and
  `PresetBrowser::Scan` (`stopThread` in their owners' destructors; calibration is cancelled first). Editor async
  callbacks capture `SafePointer`, not raw pointers.
* Co-op registry: 32 slots of lock-free atomics behind a `SharedResourcePointer`; exercised by two audio threads.
* Residual (not fixed, microsecond window): `RecordTap::allocate` after `cancel()` can reallocate the buffer while
  the audio thread is still finishing the block it entered while Recording.

## State / preset compatibility (`TestStateQa.cpp`)

* Every `Tests/fixtures/state_0.0.1_*.bin` (17 presets, 3 sessions, bit-flip and truncated variants) loads with all
  parameters finite and in range, renders finite audio, and now re-saves byte-identically in a second instance.
* A fully populated session (every parameter moved, scenes, MIDI map, history) round-trips save -> load -> save
  byte-identically, also into a populated processor and repeatedly; processing audio does not change the saved state.
* Garbage corpus: 150 random blobs (half with a valid header), 100 text truncations, 60 binary cuts, 300 mutations
  (byte flips, deletions, duplications, `nan` / `inf` / `1e999` / `-7` / `0x7fffffff` as values): no crash, every
  parameter finite and in range afterwards, and the original state still restores exactly. 3 MB attribute,
  2000-deep nesting and 20000 siblings are bounded.
* The 66 beta-1 parameter IDs are still the first 66 host indices in the same order, and every ID in
  `tools/param_ids/*.lock` exists at runtime (no duplicates).
