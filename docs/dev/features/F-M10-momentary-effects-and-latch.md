# F-M10 Momentary effects and latch controls

Status: no full spec exists. Requirements come from `10-SPEC-LIVE-CREATIVE-EFFECTS.md` 4.3 "Momentary/latch commands" and the safety rules there; placement from `11-GUI-PLACEMENT-AND-FEATURE-PLAN.md` (Performance tab). This file is the spec. F-S07 (stutter storm) and F-S12 (panic) are separate tickets that this one must cooperate with.

## 1 Summary & user-visible behaviour
Four performance buttons: **STUTTER**, **FREEZE**, **REVERSE**, **TAPE STOP**. In Momentary mode the effect plays while the control is held (mouse, MIDI note, MIDI CC >= 64, or host automation true) and releases with a short fade; in Latch mode each press toggles it on/off. It is generated by dedicated hold voices fed from live audio and mixed into the wet bus; it does not need a detected gap. Rules:
- Newest-pressed effect wins; releasing it falls back to the previous still-held effect (stack, max 4). Switching effect crossfades (<= 20 ms).
- Wet-only by default (10 section 2). A named option **Dry duck** (0-100%, default 0) lowers the dry signal while any hold is engaged so a stutter replaces rather than layers over the groove; this is the only dry-path change and is neutral at 0 (owner decision D1).
- **Protection**: by default holds ignore transient/next-event protection because the performer is in control; option "Respect protection" ducks them like fills (D2).
- Stuck-hold safety: in Momentary mode a hold with no release for `Timeout` seconds (2-60, default 15) is auto-released, the UI shows "Stuck hold released", and the control must be released and pressed again to re-engage. Latch mode has no timeout (the user chose it) but always obeys Panic.
- Algorithms (existing, no new DSP): Stutter = `Algo::Stutter` with the effective stutter division; Freeze = `Algo::Freeze` on a slice frozen at press; Reverse = `Algo::Reverse` re-anchored to the live input every segment (~250 ms) so it keeps reversing "now"; Tape Stop = `Algo::TapeStop` one-shot (decelerates, then silent wet while held; no spin-up in v1, F-M20 may add it).
- A long hold is a chain of seamless segments (<= 1000 ms, each <= the 3 s voice cap); segment N+1 starts `fadeOut` samples before N ends on the other hold voice.

## 2 Success / quality metric
- Latency: press-to-first-wet-sample <= one hop (32 samples) + the host block it arrives in; GUI press is queued, MIDI note is handled in the same block it arrives.
- Safety: 1000 random press/release/panic/transport-jump/bypass sequences (seeded fuzz) leave no stuck voice: after a final Panic the wet RMS decays below -90 dBFS within 50 ms, output finite, no sample > 1.5.
- No clicks: max sample-to-sample step during engage/release <= 1.5x the same step on a natural fill of the same algorithm.
- Neutrality: all holds off and dry duck 0 -> golden A-F bit-identical.

## 3 Design
Files: `Source/features/momentary/{HoldController.h,HoldController.cpp,MomentaryEngine.h,MomentaryEngine.cpp,Gui.h,Gui.cpp,Help.cpp}`, `Tests/features/TestMomentary.cpp`, `Source/params/fm10.{h,cpp}`, `tools/param_ids/fm10.lock`, cmake fragments.
- `HoldController` (pure logic, no JUCE, audio-thread safe, unit-testable; "feature commands separated from GUI"):
  ```cpp
  enum class Effect : std::uint8_t { Stutter, Freeze, Reverse, TapeStop, Count };
  enum class Source : std::uint8_t { Param, Midi, Gui };
  struct HoldController {
      void setMode (bool latch) noexcept;
      void setLevel (Effect, Source, bool down) noexcept;     // level input; edge handling inside
      void toggle (Effect) noexcept;                          // GUI click in Latch mode
      void tick (std::int64_t samples, std::int64_t timeoutSamples) noexcept;  // timeout accounting, once per chunk
      void panic() noexcept;                                  // clears everything, remembers nothing
      std::uint8_t engagedMask() const noexcept;              // bit per Effect (after stack + timeout)
      std::uint8_t timedOutMask() const noexcept;
      int topEffect() const noexcept;                         // newest engaged or -1
  };
  ```
  Semantics: `engaged = OR(sources)`; Momentary: engaged while any source down; Latch: each rising edge of the OR'd level, or `toggle`, flips a latched bit; timeout only for Momentary. Fixed-size arrays, no allocation.
- `MomentaryEngine` (audio thread): owns `FillVoice holdVoice[2]` (outside the pool of 4 and the preview voice; prepared in `prepare`, memory recorded like E-1), a `SourceHistory holdSource` (0.4 s) holding the freeze/stutter slice copied once at press (one memcpy <= 320 ms, same cost as a natural fill start), and a segment scheduler. API: `void process (wet, start, n, outputPos, const SourceHistory& live, const EngineSettings&, const HoldController&, float currentDuck) noexcept`; `void panic() noexcept` (requestStop(48) on both voices). Voices use `VoiceSetup` built by the shared `toVoiceSetup`/`startVoice` stages; seed = `hashCombine (seed, kSalt_Momentary + effectIndex)` + segment counter for reproducibility; no draw from the legacy `Rng`.
- Sources: (a) APVTS bool params via `ParamCache` atomics read per chunk; (b) MIDI notes scanned in `processBlock` (same scan as U-3, sets Midi level; note-off = up; matching note + channel from `<Perf>`); (c) GUI via `Command::{HoldDown, HoldUp, HoldToggle}` (extend F0-4 enum) through `commands`. GUI loses focus / mouse capture / editor destroyed while a button is down -> sends `HoldUp` (button `mouseUp`, `focusLost`, destructor).
- Dry duck: a processor-owned `juce::SmoothedValue<float> holdDryGain` (10 ms) multiplies the existing dry gain when `engagedMask != 0`; one-line hook in the dry-path section of `processChunk`; at `dryDuck == 0` the multiplier is exactly 1.0 and the code path is skipped.
- Interactions: natural fills continue unless Dry duck > 0 (then still allowed; their protection is unchanged); Panic (`FillEngine::panic`, F-S12) also calls `HoldController::panic()` and `MomentaryEngine::panic()`; Bypass: holds cleared; transport jump: holds NOT cleared (performer intent), Freeze/Stutter slices unaffected; Capture (F-M08): Reverse and live slices read via `captureStore.source()`.
- Hooks in existing files: `processBlock`/`processBlockBypassed` (MIDI scan + drain, bypass clears), `processChunk` (engine call after `engine.process`, wet add already happens on the same bus), dry gain line. Editor via `PerformanceStrip` slot.

## 4 Parameters & state
New group `GAPFILL_PARAMS_FM10` appended after the 02 group list (order permanent). Files `Source/params/fm10.{h,cpp}`, lock `tools/param_ids/fm10.lock`, append-only, version hint 1:

| ID | Type / range | Default | Unit |
|---|---|---|---|
| `fm10_stutter` | bool | off | n/a |
| `fm10_freeze` | bool | off | n/a |
| `fm10_reverse` | bool | off | n/a |
| `fm10_tape` | bool | off | n/a |
| `fm10_mode` | choice: Momentary, Latch | Momentary | n/a |
| `fm10_level` | float 0-100 | 100 | % |
| `fm10_dryDuck` | float 0-100 | 0 | % |
| `fm10_protect` | bool | off | n/a |
| `fm10_timeout` | float 2-60, step 1 | 15 | s |

- The four bools are momentary state and are never "on" after any restore: after `setStateInformation`, `applyParameterState`, preset/file load and Undo restore, `forceHoldsOff()` runs (listed in `performanceParameterIDs()`; excluded from Undo snapshots, A/B, `.gapfill` save writes 0). Random/Surprise allowlists do not contain any `fm10_*`.
- `<Perf>`: `holdNotes[4]` (0-127 or -1) and `holdChannel` (0-16), same validation as U-3. Never serialised: engaged/latched/timed-out state, voices.
- Old sessions: IDs absent -> defaults -> no hold ever engaged. Neutral proof: golden A-F + `all_off_dry_duck_0_bit_identical`.

## 5 Real-time safety
Per chunk: `HoldController::tick` (O(4)), up to 2 voice renders only while engaged, MIDI scan folded into the existing loop. Bounds: <= 2 hold voices, segment <= 1000 ms, one memcpy <= 320 ms at press (measure; if > 100 us at 192 kHz split it over blocks), stack depth 4. No allocation/locks/IO. Reset table: reset/releaseResources/sample-rate change -> panic; bypass -> panic; transport jump -> unchanged; Panic -> immediate fade (<= 48 samples). Queue full -> `HoldUp` has priority (never dropped; if `commands` is full the audio thread also times out). Denormal/NaN: via `sanitise`.

## 6 UI
- Placement: the proposed Performance tab (docs/dev/11) is not built yet; until it exists use `PerformanceStrip` slot: four 24 px-high buttons + MODE toggle (HOLD | LATCH) in a single row above the mix strip; Dry duck, level, timeout, protect live in an Advanced popover opened by a gear. No header change.
- Names/tooltips: "Stutter (hold)": "Hold to repeat the last moment of the input. Release to stop. Latch mode: click to start, click to stop."; Freeze: "Hold to freeze the last moment into a sustained texture."; Reverse: "Hold to play the recent input backwards."; Tape stop: "Hold to slow the sound to a stop, like a tape machine."
- Visuals: engaged = filled + label "ON", latched shows a lock glyph; timed out shows a hollow red outline plus text (not colour only). Status text via `FooterStatus`.
- Keyboard (when keyboard navigation is enabled): Tab focuses, Space down/up (hold) or toggle (latch); `Esc` = release all (not Panic). Accessibility names include state ("Stutter, held", "Stutter, latched").
- Reduced Motion: no pulse; state text only. Narrow: buttons shrink to 4 equal columns >= 24 px; popover content scrolls internally.
- Help (order 1900): holds, modes, timeout, dry duck, protection, "Tape stop does not spin back up".

## 7 MIDI / automation / CLAP / host
- Parameters are host-automatable (automation lane = hold), CC-learnable via the existing right-click menu (CC >= 64 down, < 64 up; Latch uses rising edge). Notes via `<Perf>` mapping (Learn: next NoteOn within 10 s, same bounded rules as CC learn). Hold notes are consumed for control only: `producesMidi()` stays false and no MIDI is thrown away that other effects need (GapFill is not a MIDI passthrough).
- Lost note-off, controller disconnect, host stop mid-hold: handled by Timeout (Momentary) and Panic; transport stop does not release (documented).
- CLAP: stepped bool parameters. Offline render: automation-driven holds are deterministic; GUI/MIDI-driven holds are not replayable (documented).
- Dry duck changes the dry level only while engaged; latency/PDC unchanged.

## 10 Effort & risks
Effort L. Risks: (1) dry-path edit (D1) is the first place GapFill touches the dry signal for performance; (2) default for protection (D2); (3) two more `FillVoice` instances of memory; (4) hosts that swallow MIDI notes for instruments-only; (5) users expect a Performance tab (not yet built, slot fallback); (6) bool parameters in preset files must stay 0.
Decisions: D1 include Dry duck at all (alternative: wet-only strictly); D2 default of "Respect protection".
