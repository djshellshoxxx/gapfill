## Compatibility refinement

Existing `coopMode` and `coopGroup` must retain their old choice counts **and**
integer values. Appending an enum choice changes normalized host automation:
old mode 0.5 maps to Alternate, but four choices would map it to Follow. Therefore
do not append public choices to either released parameter. The internal engine
may use Deterministic=3, selected through new tail-group parameters instead.

Proposed COOPEXT tail parameters, centrally registered after the released FM10
tail and other coordinated extension groups:

| ID | Type/default | Behavior |
|---|---|---|
| `coopDeterministic` | bool, false | Select new deterministic engine; false retains exact legacy modes. |
| `coopDetGroup` | Use legacy group, A–H; default Use legacy group | Does not alter the released group parameter's normalization. |
| `coopSlot` | integer 1–32, 1 | Stable musical identity, distinct from a process lifetime token. |
| `coopPriority` | integer percent 0–100, 50 | Weighted ownership; zero retains the specified small floor weight. |
| `coopYield` | percent 0–100, 70 | Reduces non-owner density/fill, never increases either. |
| `coopGrid` | Beat/Two beats/Bar/Two bars/Four bars, Bar | Shared election time grid. |

Group, slot and grid are not automatable. Every new ID is performance state,
excluded from Random/Surprise/Undo and scene capture. All old parameter IDs,
indices, ranges and saved integer/normalized values stay unchanged.

## Completed pure-model slice

`Source/features/coop/Deterministic.h` provides immutable bounded snapshots,
validation, weighted rendezvous ownership, musical slot calculation and yield
scales. Election uses the existing permanent co-op salt, musical group/time-slot
and fixed member slots. Runtime lifetime tokens, array order and thread order are
not random inputs. Tokens still detect duplicated/recycled membership records.

- Exactly one owner over 64 bars for four equal members; Yield100 gives every
  non-owner zero density.
- 2,000-slot priority shares within three percentage points of 10/20/30/40%.
- Removing a non-owner leaves ownership unchanged.
- Changed runtime tokens and reversed input membership order leave election unchanged.
- One/four threads and 64/512-block decision-position reconstruction agree.
- Invalid/duplicate membership rejected; negative pre-roll and 7/8 grid tested.
- Yield is neutral for owners and bounded/reducing for non-owners.

## Production module implementation and coordinator hooks

- Separate bounded deterministic registry; preserve the existing legacy registry
  layout/capacity and behavior. Packed lifetime records must publish atomically;
  no processor pointers, token reuse or partial records.
- Coherent versioned roster proposals with shared future musical activation.
  Register callbacks' complete admitted ranges before a proposal becomes visible,
  so no callback has already rendered across a newly published boundary.
  Retain previous/current snapshots until every live member no longer needs the
  previous version; use bounded retries and a visible fail-closed diagnostic.
- Production decision hook applies non-owner yield before the probability roll,
  and rejects at Yield100 without advancing new RNG state.
- New group recall carries generation, scene index, exact common PPQ deadline and
  cancellation/membership generations. It never sends pointers to another instance.
  `SceneController::gotoSceneAt` resolves the receiving instance's bank locally;
  late/invalid adoption must cancel, not fall back to a different boundary.
- GUI/Help/ParamInfo, duplicate-slot repair, group status and capacities.

The bounded membership, cancellation channel, `CoopMember` adapter, parameter
builders, ParamInfo/Help and Advanced performance card are now implemented in this
branch. Root owns their shared registration and processor/engine/LiveControl hooks.

1. Register COOPEXT **after WETBUSEXT**, keeping all 216 released indices and old
   `coopMode`/`coopGroup` choice counts unchanged. New builder functions are
   `addCoopextParameters` and `addCoopextPerformanceIds`. CMake fragments discover
   the new definitions, GUI and tests without top-level CMake edits.
2. Root's approved nonconst `getCoop()` accessor is required by the GUI. Build a
   `coop::DeterministicConfig`: group is `coopDetGroup` when nonzero, otherwise
   `coopGroup`; slot/priority/yield/grid come from their six new parameters.
   Only when `coopDeterministic` is on, call `configureDeterministic(config)` in
   **prepare for every instance before any instance renders**. This reserves
   unique fixed slots without an editor. Off configurations retain the original
   `beginChunk` path and released output behavior.
3. After transport is available in each processed chunk, select
   `beginDeterministicChunk(config, {valid, ppq, samplesPerBeat, beatsPerBar,
   numSamples})` instead of legacy `beginChunk`. Put its returned pointer into
   `EngineSettings::perf.coop`. A new joining member waits for the common future
   roster; contention/capacity failures pause natural fills with visible status,
   never choose an alternative owner. Unavailable transport stays neutral.
4. In `FillEngine::trySchedule`, after `Effective::applyAtDecision`, apply
   `coop::yieldScale(*view, havePpq, ppq)` to the local density/fill **only for the
   new deterministic mode and natural decisions**. Preserve explicit Fill Now's
   existing exemption. The existing `checkEligibility` call to `coop::evaluate`
   rejects full non-owner yield and waiting membership before RNG seeding/draws.
   Partial yield scales probability instead of becoming a binary rejection.
5. On the existing transport-jump path call `CoopMember::noteTransportJump()`.
   On panic/stop call `cancelGroupScenes()` as well as the existing local cancel.
   `release()` and destruction free both memberships and cancel group recalls.
6. Root's message pump, including with the editor closed, calls
   `repairDuplicateSlot()` and synchronizes
   `pendingSlotForHost(currentRequestedSlot)` with the normal host gesture path.
   A differing newer user request must win. Before serializing a **private APVTS
   copy** for host state or preset save, call `applyAssignedSlotToState(copy)`;
   this preserves the actual reserved slot even before the slower message tick.
7. Message-thread `pollGroupSceneEvent(event)` returns one of
   `GroupSceneEvent::Recall/Cancel` with group, sceneIndex, absolute targetPpq,
   generation, cancelGeneration and membershipGeneration. Drain bounded requests;
   Recall uses `SceneController::gotoSceneAt(index, ppq, group, cancelGeneration)`;
   Cancel cancels pending local recall. While panicked, consume/discard recalls.
   Missing/late/invalid local scenes report a receiver-specific rejection, never
   late fallback or a cross-host atomic-commit promise.
8. **Before** the audio scene-boundary check, compare the coherently published
   Overlay externalGroup/externalCancelEpoch with
   `CoopMember::groupCancelGeneration(group)` and cancel pending mismatch. State
   commit `ced4ae6` supplies this guard metadata and fixed-deadline API. A separate
   unbound atomic tag could attach cancellation to the wrong pending request.

- **21 pure tests passed** with
  `g++ -std=c++20 -pthread -Wall -Wextra -Wpedantic -Wconversion -Wshadow -Werror`.
  Compile all three `TestCoopDeterministic.cpp`, `TestCoopRegistry.cpp`,

- The same **21 passed under ASan+UBSan** with `ASAN_OPTIONS=detect_leaks=0`.
  Default LeakSanitizer exits fatally because this execution environment uses
  ptrace; no leak-sanitizer pass is claimed. Run leak checks in a supported runner.
- `Coop.cpp`, `coopext.cpp` and `Info.cpp` pass JUCE syntax checks with
  `-Wall -Wextra -Wconversion -Wshadow -Werror`, treating JUCE includes as system
  headers. GUI syntax/native linkage awaits the coordinator's nonconst getter
  and registry integration. Broad GUI-header `-Wshadow` checking also exposes
  existing RcrushCard/TapeDestrCard/MatchLevels warnings outside this module.
- Seven additional native GF tests are registered in `TestCoop.cpp`: released
  normalization, automatic fixed-slot/state-copy preservation, 64-bar adapter
  ownership, partial yield, shared scene deadline/cancellation and allocation
  guard. They are **not yet executed** by this standalone verification.
- Local diagnostic benchmark: 32-member stable roster, cached owner evaluation,
  update/maintain/admit at 48 kHz/512: approximately **50 ns/callback**,
  **0.00047% of one core** on this execution machine. This is not the specified
  reference-machine or integrated-processor performance acceptance. Recheck it
  with the actual source/build fingerprint and integrated interactions.
- Owner caching is private to each audio-owned `View`, keyed by roster generation,
  musical time slot and lifetime token. Shared immutable Snapshot election remains
  pure. Tests invalidate the cache across slots and yield changes. A demonstrated
  last-ulp PPQ boundary discrepancy was fixed with a 1e-9-beat allowance, below
  one supported audio sample; actual early positions are still the preceding slot.
- A 44-bit signed fixed-point PPQ admission frontier plus a 20-bit monotonic roster
  generation prevents stale publication CAS/ABA. Generation/lifetime exhaustion
  refuses new work rather than wrapping. Previously needed versions are retained;
  inactive peers can delay changes, and the status explains that wait. No stale
  wall-clock timeout changes deterministic ownership.
