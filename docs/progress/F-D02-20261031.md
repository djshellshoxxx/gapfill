# Event command compatibility — 2026-10-31

The event writer retains the format1 layout, record IDs1–5, command flags,
signed index bytes, velocity bytes and 24-byte little-endian records. A legacy
format1 recipe command can still load and save as format1 with its historical
payload-free behavior.

New recordings of LikeRecipe, LockRecipe, PreviewRecipe and SkipRecipe append
RecipePayload record6 immediately after the existing Command record. Its final
16 bytes contain the existing portable FillRecipe encoding; its command type
and block must match. The ring publishes both records atomically. If the record
cap cannot fit both, neither is published and recording stops as incomplete.

Recipe payloads and appended commands31–33 require XML format2. The previous
reader requires format1, so it explicitly rejects these files. The new reader
accepts formats1 and2, rejects future formats, unknown command/type IDs, orphan
or missing payloads and invalid recipes before replacing caller output. Replay
uses the same command decoder and preserves recipe, index and velocity; replayed
commands are unstamped rather than inheriting an old wall-clock timestamp.

Evidence: the new EventsCodec regressions initially produced four failures
(missing payload, old format, malformed-pair acceptance prerequisites and partial
record-cap behavior). Seven focused native tests now pass under strict warnings
and separately ASan+UBSan, including legacy byte equality and concurrent draining
across a 256-record batch boundary. LSan was disabled for the runner's ptrace
restriction. Raw logs are in `/workspace/work/evidence/midi/events-codec-*.log`.

These are focused recorder/codec results using JUCE core. Full processor replay,
