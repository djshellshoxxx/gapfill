# F-L24 controller completion contract

The approved implementation extends the existing JSON profile formats with schema 3. Schemas 1 and 2, their command sets, compiled profiles, the Commands table, and the authoritative MIDIMAP CC/id state keep their established behavior. Files remain bounded to 8 KiB. New schema 3 accepts up to 64 parameter bindings (stable id, CC, channel 0 Omni or 1..16, Jump or Pickup), up to 16 indicators, an explicit parameter-feedback switch (off by default), and transmit channel 1..16. Duplicate CC/parameter ownership and command overlaps are rejected before mutation. Optional Controllers v1 state is separately bounded to 8 KiB and restores configuration atomically; absent state means Omni/Jump and no new feedback.

Pickup accepts within 2/127 of the current normalized value or on crossing it; external parameter changes re-arm it. The audio path uses bounded preallocated atomics and the existing scanner, preserving same-block Panic and the established one-block queued command timing. Feedback uses a separate enabled-only 30 Hz message timer. A pure policy receives an explicit monotonic clock: at most 30 sends per second/address, 512 sends per second globally, 250 ms input echo suppression, changed values only, and a full resync spread over at most 200 ms. Device retry is at most 100 ms while enabled; loss releases held states while preserving mappings, return resyncs within 500 ms.

Standalone device calls stay on the message thread. Opt-in plugin feedback uses a fixed 256-event SPSC queue; the processor drains only the remaining portion of its shared 32-event callback budget after musical output and required note-offs. GAPFILL_MIDI_OUT stays off by default, and AU output remains unavailable. Host and physical motor/pad-controller results require actual evidence and remain unverified until exercised.

Contract headers: controller/ControllerTypes.h, Takeover.h, FeedbackCore.h. Integration and evidence are pending; these declarations are not a completion claim.
