## Deviations and known gaps (honest list)

* **Golden length**: 4 bars at 150 BPM (6.4 s) instead of 8 bars, to keep six stereo `.f32` baselines at ~2.5 MB each (14.7 MB). Rendering is ~60 ms per scenario, so lengthening is cheap if repository size is acceptable. Only `Tests/golden/linux` exists; **Windows/macOS baselines are unverified** (the test prints `UNVERIFIED` when the platform directory is missing; run `tools/dev/write_golden.sh` there in a `[golden]` PR).
* **State fixtures** were generated by the pre-refactor build through `getStateInformation` (which is the 0.0.1 format) rather than by an actual 0.0.1 binary.
* **Reject reasons**: `FillOff`, `TooShort`, `DensityRoll`, `NoAlgoFits`, `NoBand`, `NoVoice` are reached from audio renders; `NoSource`, `TooSoon` through the eligibility stage directly; `GuardEaten` through `noRoomReason`. `SourceUnavailable` (voice cannot start even after the Granular fallback) is defensive and has no synthetic trigger; `LockSkipped` and the six doc-12 reasons are produced by features not yet written.
* **Slots**: only `CreativeExtra`, `VisualiserOverlay` and `FooterStatus` have a reserved rectangle in `resized()`; the other slots stay empty (their components are hidden) until their first feature reserves a rectangle. `kMinWidth/kMinHeight` unchanged (1020 x 620).
* **Sidebar**: the CAPTURE toggle is now a direct child of the editor (via `SlotHost`) rather than of the Creative panel; position and size are unchanged, keyboard traversal order may differ slightly (not verified in a real host).
* `performanceParameterIDs()` exists (contains `capture`; groups append theirs). The validator rule "a new parameter must be classified" is **not** implemented; only the disjointness test exists.
* `Effective` stage files and `gather*` lines are empty placeholders; no feature logic landed.
* clang-tidy/clang-format configs are added but were not run (not installed here).
* Windows (MSVC/clang-cl) build and pluginval/clap-validator were not run here.

## Measured numbers (Linux, gcc Release, shared 4-core VM)

* `sizeof(FillVoice)` = 2584 bytes, `sizeof(FillEngine)` = 10904 bytes (4 voices; voice sample buffers live on the heap and are not included). History buffer = 6 s x sr x 2 ch x 4 B (2.3 MB at 48 kHz, 9.2 MB at 192 kHz) plus per-voice capture/comb buffers.
* `prepareToPlay` global-`operator new` traffic is 485 KiB in 131 allocations at both rates; **this undercounts** (JUCE `HeapBlock`/`AudioBuffer` use `malloc` and bypass the counter), so use the analytic figure above for budgeting.
* `processBlock` at 512 samples / 48 kHz, scenario E (complexity 100, chaos 100, fill 100): mean 108-113 us (about 1.0-1.1 % of the 10.7 ms block), p99.9 about 580 us. Stored in `Tests/perf_baseline.json`; enforcement opt-in with `GAPFILL_PERF_ENFORCE=1`.
* Audio thread allocation: zero allocations in steady state (`steady_state_audio_thread_does_not_allocate`).
* Test suite: 87 original tests + new ones; see the final run in the hand-off.
