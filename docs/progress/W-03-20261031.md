# W-03 pure transport-predicate extraction — 2026-10-31

Scope: characterize and extract the released callback-level predicate from

## Contract

`Source/features/transport/TransportTracker.h` has no JUCE dependency and no
allocation, locks, clock access or callbacks. State has one owner on the processing
thread. The adapter supplies a `TransportSample` once per **whole host callback**,
including stopped and bypassed callbacks, never again for an internal sub-chunk.

```cpp
struct TransportSample
{
    bool playing, ppqValid;
    double ppq, bpm;
    int blockSamples;
};

enum class JumpKind { None, Start, Stop, Discontinuity };
```

Use `TransportTracker::prepare(sampleRate)`, `reset()` and
`update(const TransportSample&) noexcept`. The adapter already resolves invalid
host tempo to 120 BPM and validates finite PPQ. Preserve that boundary rather than
giving the helper a second contradictory host-validation policy.

| Input transition | Output | Existing processor effect |
|---|---|---|
| Stopped → playing, with or without PPQ | Start | `noteTransportJump`, context reset, wet panic, jump counter |
| Playing → stopped | Stop, once | Wet panic only; do not increment jump count |
| Playing, lose valid PPQ | Discontinuity, once | Same as Start |
| Playing, PPQ returns | Discontinuity, once | Same as Start |
| PPQ differs from previously projected callback end by **more than** 0.25 beat | Discontinuity | Same as Start |
| Continuous playback, exactly ±0.25 beat discrepancy | None | None |
| Playing without PPQ for later callbacks | None | None |

The old prediction is `ppq + hostBlockSamples / (60.0 / bpm * sampleRate)`, saved
at the end of each playing callback using that callback's resolved BPM. Preserve
the operation order and previous **complete** callback length. No average-tempo
estimator or tolerance tightening is included.

Important preparation nuance: the released `prepareToPlay` updates the sample rate
but does not clear the old transport history; `reset()` clears it, and
`releaseResources()` invokes reset. Therefore `prepare(sr)` updates the helper's
rate **without implicitly resetting**. Changing this would be a separate behavior
fix, not a faithful extraction. Initial construction already starts reset.
